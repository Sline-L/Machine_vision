# GearPro 新版架构与运行说明

## 检测方案

新版按照《优化方案》中的“检测两次”和模型拆分思路实现两阶段推理：

1. `model/model1.pt`：YOLO 检测模型，类别元数据为 `gear`，负责从相机原图定位齿轮。
2. 程序按定位框裁剪齿轮 ROI，并保留约 4% 的边缘区域。
3. `model/model2.pt`：ResNet18 二分类模型，输入尺寸由模型元数据读取（当前为 512），
   输出经过 sigmoid 后作为缺陷概率。
4. 缺陷概率达到设置阈值时判为“不合格”，否则判为“合格”。

分类预处理使用 RGB、缩放到模型尺寸、ImageNet mean/std 归一化。这一点无法仅从权重
中验证；如果 `model2.pt` 训练时使用了其他归一化参数，应同步修改
`gearpro_models.py` 的 `_defect_score()`。

串口协议沿用旧版：合格发送 `01`，不合格发送 `02`。为避免同一齿轮在连续帧中被
重复计数和重复发送，默认使用 5 秒冷却时间。

## 模块职责

```text
gearpro_main.py       应用入口与 Qt 环境初始化
gearpro_config.py     路径、硬件和检测参数
gearpro_camera.py     相机采集、显示和线程安全帧缓冲
gearpro_models.py     YOLO 定位 + ResNet18 缺陷分类
gearpro_worker.py     后台推理线程
gearpro_serial.py     串口连接与结果发送
gearpro_types.py      检测结果和统计数据对象
gearpro_ui.py         主界面、设置界面和统计图
```

UI 线程只负责相机刷新和界面更新，模型加载及推理均在独立 `QThread` 中完成。帧缓冲只
保存最新一帧，不积压过期画面。

## 安装与启动

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python gearpro_main.py
```

程序保持旧版硬件默认值：摄像头索引 `2`、串口 `/dev/ttyHS1`、波特率 `9600`、齿轮
定位置信度 `0.70`。可在右上角“设置”中调整运行模式、阈值、推理间隔和摄像头索引。

部署时也可用环境变量覆盖易变路径：

```bash
GEARPRO_CAMERA_INDEX=0 \
GEARPRO_SERIAL_PORT=/dev/ttyUSB0 \
GEARPRO_MODEL1=/path/to/model1.pt \
GEARPRO_MODEL2=/path/to/model2.pt \
python gearpro_main.py
```

## 旧版运行

旧程序及实验脚本保存在 `legacy/`，旧主程序仍可直接运行：

```bash
python legacy/gp_main.py
```

旧程序与新版相互独立，不共享运行状态或模块。

## 当前边界

- 当前计数防抖沿用固定冷却时间。接入稳定的光电传感器后，建议改为传感器触发一次、
  推理一次，这比仅依赖画面时间间隔更可靠。
- 模型推理速度与阈值必须在目标 Jetson 和实际工业相机上标定。
- 无齿轮时不计数、不发送串口数据；同一帧内任一齿轮被判为缺陷，则整帧结果为不合格。
