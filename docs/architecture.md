# GearPro 系统架构

## 1. 系统目标

GearPro 面向传送带齿轮的实时质量检测。程序从工业相机或 USB 摄像头获取画面，通过
两阶段模型识别齿轮并判断缺陷，随后更新界面统计，并把判定结果发送给外部控制设备。

## 2. 两阶段检测流程

```text
摄像头原图
    │
    ▼
model/model1.pt（YOLO，类别 gear）
    │ 定位框
    ▼
裁剪齿轮 ROI（保留约 4% 边缘）
    │
    ▼
model/model2.pt（ResNet18，输入 512×512）
    │ sigmoid 缺陷概率
    ▼
阈值判定 ──► UI、统计、串口
```

模型 1 避免把完整相机画面直接压缩后交给缺陷分类器；模型 2 在较高有效分辨率的 ROI
上识别划痕、缺齿等缺陷。当前分类预处理为 BGR 转 RGB、缩放至模型元数据给出的尺寸，
再使用 ImageNet mean/std 归一化。如果分类模型训练时采用了其他归一化参数，必须同步
修改 `gp/models.py`。

当同一帧包含多个齿轮时，只要任一 ROI 达到缺陷阈值，整帧判为不合格。未检测到齿轮
时不计数、不发送串口数据。当前使用 5 秒冷却时间防止同一齿轮在连续帧中重复计数。

## 3. 运行结构

`gp/` 是新版应用包：

| 模块 | 职责 |
| --- | --- |
| `app.py` | Qt 平台初始化、应用创建与启动 |
| `camera.py` | 相机采集、原图显示、线程安全最新帧缓冲 |
| `config.py` | 项目路径、硬件默认值和运行参数 |
| `models.py` | YOLO 定位与 ResNet18 分类流水线；唯一绑定模型格式的模块 |
| `worker.py` | 模型加载和后台推理线程 |
| `serial_io.py` | 串口懒连接及判定代码发送 |
| `types.py` | 检测结果与统计数据对象 |
| `ui.py` | 主界面、设置窗口和统计图 |

UI 线程负责相机刷新与界面绘制，模型加载和推理在独立 `QThread` 中执行。帧缓冲只保存
最新一帧，不建立积压队列。根目录 `gp_main.py` 与 `python -m gp` 最终都调用
`gp.app.main()`。在 Wayland 会话中程序优先使用 Qt Wayland 平台插件，在 X11 会话中使用
`xcb`；导入 OpenCV 后会恢复 PyQt5 自带的插件目录，避免加载 `cv2/qt/plugins`。

视频测试模式由推理线程直接打开视频并按原始帧率顺序读取，确保测试帧不会被实时相机的
“最新帧”策略跳过。可通过 `--video` 参数或界面文件选择器进入；该模式自动开始识别、
禁用串口输出，并在视频结束后保留最终画面和统计结果。

## 4. 配置与接口

默认硬件参数保持为摄像头索引 `2`、串口 `/dev/ttyHS1`、波特率 `9600`。定位置信度
默认 `0.70`，缺陷阈值默认 `0.50`。运行时可在右上角“设置”中修改模式、阈值、推理
间隔、摄像头和串口。

部署环境变量：

| 变量 | 作用 |
| --- | --- |
| `GEARPRO_CAMERA_INDEX` | 摄像头索引 |
| `GEARPRO_SERIAL_PORT` | 串口设备路径 |
| `GEARPRO_MODEL1` | 齿轮定位模型路径 |
| `GEARPRO_MODEL2` | 缺陷分类模型路径 |

串口协议沿用旧版：合格发送 ASCII `01`，不合格发送 ASCII `02`。模型路径目前
默认为 `.pt`；换成 `.onnx` 或 `.engine` 时仍通过上述环境变量指向新文件。
格式选择与上板步骤见 [模型格式](model-formats.md)。

## 5. 当前边界

- 模型阈值、冷却时间和推理速度需在目标 Jetson、工业相机及实际传送带上标定。
- 第一次上 NX 应继续使用 `.pt` 建立延迟与精度基线；ONNX / TensorRT 是后续
  加速手段，不要求先改应用结构。
- 固定冷却时间不是严格的零件追踪；接入光电传感器后应改为一次触发对应一次检测。
- 摄像头采集仍使用 OpenCV V4L2，其他平台需要更换或自动选择后端。
- 内置 `ultralytics/` 源码和模型在对外分发前需要单独确认许可证兼容性。
