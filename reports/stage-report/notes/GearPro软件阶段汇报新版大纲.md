# GearPro 软件阶段汇报新版大纲

> 面向指导老师的项目进展汇报
>
> 建议页数：19 页
>
> 建议总时长：15–20 分钟，其中现场演示约 3 分钟

## 总体阐述逻辑

本次汇报采用“当前结论先行，再用关键技术决策解释结果”的结构，不按训练版本逐项复述，也不只展示最终界面。

> 当前取得了什么成果 → 如何评价结果 → 数据是否可信 → 为什么形成当前架构 → 两个专项怎样工作 → 当前差距在哪里 → 软件如何落地 → 下一阶段怎样通过实验优化

探索过程只保留真正改变技术路线的证据：

- 微小划痕在整图缩放后可能只剩少量像素，因此采用 Model1 定位与高分辨率 ROI。
- 统一任意缺陷模型在联合锁定测试上的泛化不足，因此按视觉机理拆分 Scratch 与 Missing Hole 专项。
- P2 对细小划痕有价值，但没有在 Missing Hole 任务上体现稳定优势，因此两个专项采用不同检测结构。
- 两个专项分别校准、分别过阈值，最终执行 OR，在提高 Recall 的同时也会合并误报。
- 当前错误集中在低对比划痕、斜视缺口和高光正常样本，因此下一阶段优先改善成像、数据覆盖与几何一致性，再进行部署加速。

汇报中始终区分三种状态：

- **已实现：**当前 main-web 分支已有代码、配置或测试支持。
- **已有实验：**研究分支留下了可核对的对照结果，但不一定进入当前运行时。
- **候选方案：**来自错误分析和《优化方案》的下一阶段研究假设，尚不能表述为已有能力。

- 结果同时进入 Web 页面、运行统计和串口输出。
- 本次重点回答：为什么采用当前技术路线、实验结果是否可信、当前结果怎样进入实际软件。
- 开场主动说明离线锁定测试不能替代真实相机、照明、传送结构和执行机构的端到端验收。

# 第 3 页　任务定义与评价标准

## 本页作用

锁定业务目标和评价口径，为后面的模型比较、阈值选择和优化优先级建立统一标准。

## 主要内容概括

视觉任务包含齿轮定位、划痕识别和缺齿缺口识别。评价重点不是单一 Accuracy，而是同时控制缺陷漏检和正常品误剔除。

## 详细内容与技术细节

- Model1 产生 ROI；定位失败会直接造成后续专项无输入。
- Scratch 专项判断低对比、局部纹理型缺陷。
- Missing Hole 专项判断齿形和轮廓发生变化的结构型缺陷。
- Recall 表示真实缺陷中被检出的比例，对应漏检风险。
- FPR 表示正常样本被误判为缺陷的比例，对应正常品误剔除。
- Precision 用于分析剔除结果的可信度，但会受缺陷发生比例影响。
- mAP 用于分析辅助检测框质量，不直接等同于最终工件判定能力。
- 阶段目标为 Recall ≥ 0.95、FPR ≤ 0.20，两个约束必须同时满足。

## 建议展示内容

- 左侧画定位、划痕和缺口三个任务。
- 右侧画 Recall 和 FPR 的业务含义，不只展示公式。
- 标注“锁定测试口径”和“真实产线口径”不同。

## 可能问题

- 为什么不以 Accuracy 为主要指标？
- 为什么不只看 Precision、F1 或 mAP？
- 定位模型的漏检怎样计入最终端到端 Recall？
- FPR 上限 0.20 的业务依据是什么？

# 第 4 页　当前端到端视觉处理流程

## 本页作用

给出贯穿整场汇报的系统总图，后续每个技术决策都能回到这条真实运行链路。

## 主要内容概括

系统先定位齿轮并裁剪 ROI，再让两个专项独立判断，最后执行 OR，将同一结果用于页面、统计和硬件输出。

## 详细内容与技术细节

    相机或测试视频
    → Model1 定位齿轮
    → 定位框宽高方向各外扩 4%
    → 裁剪齿轮 ROI
    → Scratch V5 与 Missing Hole V1 顺序推理
    → 各自温度校准、概率融合和阈值判断
    → 两个专项执行 OR
    → Web、统计和串口输出

- 同一帧存在多个齿轮时逐个生成 ROI，任意齿轮命中任意专项即判定整帧不合格。
- 未定位到齿轮时不计数，也不发送串口结果。
- 合格发送 ASCII 01，不合格发送 ASCII 02。
- 视频测试模式始终禁用串口，防止测试素材触发真实执行机构。
- 默认使用冷却时间避免同一齿轮在连续帧中被重复计数；当前尚未实现逐工件 ID 跟踪。

## 建议展示内容

- 一条从左到右的主流程，突出两个专项和最终 OR。
- 输入端标明实时相机与视频测试，输出端标明 Web 与串口。
- 用小注释标出 ROI 外扩、无齿轮跳过和视频串口隔离。

## 可能问题

- 为什么两个专项顺序执行，而不是并行执行？
- 一帧有多个齿轮时，统计单位是什么？
- 冷却时间是否可能漏掉相邻工件？

# 第 5 页　数据拆分与实验可信度

## 本页作用

证明后面的模型结果不是由连续帧泄漏或反复使用测试集得到的，并说明当前指标的可信边界。

## 主要内容概括

同一工件和相近拍摄序列必须按组隔离；训练、验证和锁定测试承担不同职责，锁定测试不能继续用于调参。

## 详细内容与技术细节

- SHA256 检查完全相同的文件。
- dHash 发现视觉上高度相似的图片，但哈希相近不自动等同于泄漏，还要结合视角、背景和工件来源复核。
- 结合连续序号、宽高比和灰度相关性建立近重复组，同组不跨训练和验证集合。
- 训练集更新模型参数；验证集选择结构、温度、融合权重和阈值。
- 锁定测试只在配置冻结后使用，查看结果后不能再根据它修改阈值。
- Missing Hole 的训练池与 test 没有 SHA256 重复，也没有 dHash 距离不大于 2 的跨集合近重复。
- Scratch 的精确重复为 0，但存在 75 对感知哈希近似项，需要结合图像复核。
- 150 张测试图适合作为当前迁移基线，但不足以代表全部齿轮、批次、视角、设备和照明条件。

## 建议展示内容

- 训练、验证、锁定测试三段流程图。
- 右侧展示“允许做什么／禁止做什么”。
- 可放一组近重复图片示意，但不把哈希数值直接当作泄漏结论。

## 可能问题

- 为什么感知哈希相近不一定构成数据泄漏？
- 训练集与测试集来自不同批次吗？
- 150 张测试集的统计稳定性如何？
- 为什么不能继续使用当前 test 调阈值？

# 第 6 页　关键决策一：先定位齿轮，再识别缺陷

## 本页作用

从微小缺陷的像素保留和背景干扰解释两阶段方案，而不是把“先定位再分类”描述成经验选择。

## 主要内容概括

整图缩放会进一步压缩划痕像素；先定位并裁剪 ROI，可以把输入分辨率集中到齿轮表面，同时降低背景与姿态干扰。

## 详细内容与技术细节

- 原始图中的微小划痕可能只有少量像素，经过整图缩放和连续下采样后，特征可能不足一个有效网格。
- Model1 解决“齿轮在哪里”，专项模型解决“齿轮有什么缺陷”。
- 定位框宽、高方向各外扩 4%，用于保留边缘缺陷和少量上下文。
- ROI 方案比完全依赖传送带机械定位更具适应性，但仍要求原图具有足够分辨率和正确对焦。
- 固定相机让齿轮占满画面可以减少定位成本，但会降低对尺寸、位置和工装变化的适应能力。
- Model1 漏定位属于端到端漏检，正式验收不能只统计预裁 ROI 上的专项成绩。

## 建议展示内容

- 对比“整帧缩放”和“定位后 ROI”两种像素路径。
- 显示缺陷从原图到 P2、P3 特征层时的尺寸变化。
- 将 4% 外扩标在真实 ROI 示例上。

## 可能问题

- 4% 外扩是怎样确定的？
- 如果缺陷位于定位框之外怎么办？
- 为什么不通过机械结构直接保证齿轮占满画面？
- Model1 是否应该和专项模型联合训练？

# 第 7 页　关键决策二：从统一模型转向双专项

## 本页作用

用锁定测试和缺陷机理说明架构变化，体现探索过程中的技术判断。

## 主要内容概括

统一模型结构更简单，但在当前数据条件下同时学习微小纹理和结构缺口时泛化较弱，因此拆分为两个专项模型。

## 详细内容与技术细节

- 统一 EfficientNet-B0 任意缺陷模型在联合锁定 test 上的 Recall 为 0.7606，FPR 为 0.4177。
- 双专项 OR 在同一联合 test 上的 Recall 为 0.8873，FPR 为 0.2278。
- 划痕主要表现为小面积、低对比纹理变化；缺齿缺口主要表现为齿形和轮廓结构变化。
- 统一任务下，两类缺陷可能要求不同输入尺度、检测头和错误负样本，有限数据会分散监督信号。
- 双专项允许分别校准概率、选择阈值和分析错误子组，代价是推理量与维护成本增加。
- 该结论只适用于当前数据和训练方案，不能表述为统一模型未来永久不可行。

## 建议展示内容

- 左侧放统一模型，右侧放双专项，中央放同口径 Recall/FPR 对比。
- 用简化探索线表示“统一任务 → 错误分析 → 专项拆分”。
- 标明决策依据是锁定测试，而不是验证集最高分。

## 可能问题

- 双专项性能提升是否只是参数量增加造成的？
- 为什么不采用共享 backbone 的多任务模型？
- 如果数据增加，是否应该重新评估统一模型？
- 两个专项的计算开销是否满足 Jetson 实时要求？

# 第 8 页　Scratch V5：整体分类与局部检测互补

## 本页作用

深入讲解划痕专项的结构、概率处理和锁定测试结果，展示模型设计与缺陷尺度的对应关系。

## 主要内容概括

两个分类器判断 ROI 的整体外观，P2 检测器强化细小局部划痕，三路概率经过温度校准后加权融合。

## 详细内容与技术细节

- 分类器为 EfficientNet-B0 和 ResNet18，输入尺寸均为 384。
- 检测器为 YOLO26-P2，输入尺寸为 960。
- 三路概率先独立执行温度校准，温度写入发布配置，不在运行时随意调整。
- 两个分类概率取均值后融合：

    scratch_probability
    = 0.25 × classifier_probability
    + 0.75 × detector_probability

- 发布阈值为 0.300273610279458。
- 辅助框显示门槛为 0.05，但融合仍使用更低的检测概率；框本身不决定最终判定。
- 锁定测试共 150 张，其中划痕 31 张、正常 119 张。
- Recall 0.8065、Precision 0.5556、FPR 0.1681，TP/FP/TN/FN 为 25/20/99/6。
- 主要 FN 是低对比、小面积或外观不稳定的划痕；主要 FP 来自侧齿高光和正常加工纹。

## 建议展示内容

- 三路模型汇聚到一个融合公式。
- 同时展示一个 TP、一个低对比 FN 和一个高光 FP。
- 指标区使用混淆矩阵，不只展示单一 Recall。

## 可能问题

- 为什么选择两个分类器而不是一个更大的分类器？
- 为什么检测器权重为 0.75？
- P2 带来的精度收益和计算代价分别是多少？
- 验证集与锁定测试为什么差距较大？

# 第 9 页　Missing Hole V1：结构缺陷专项

## 本页作用

说明缺齿缺口任务没有照搬 Scratch 的结构，而是根据实验选择标准检测头和不同融合比例。

## 主要内容概括

Missing Hole V1 同样结合图像级分类和局部检测，但使用标准 YOLO26n，并把分类均值与检测概率等权融合。

## 详细内容与技术细节

- EfficientNet-B0 输入尺寸为 512，ResNet18 输入尺寸为 384。
- 检测器使用标准单类 YOLO26n，输入尺寸为 960。
- P2 在该任务上没有带来稳定收益，因此没有因为“目标可能较小”就默认保留 P2。
- 融合公式：

    missing_hole_probability
    = 0.50 × classifier_probability
    + 0.50 × detector_probability

- 发布阈值为 0.3413327979078584。
- 锁定测试共 150 张，其中缺陷 44 张、正常 106 张。
- Recall 0.8182、Precision 0.9000、FPR 0.0377，TP/FP/TN/FN 为 36/4/102/8。
- 位置子组 Recall：bottom 0.9167、side 1.0000、oblique 0.5882。
- 不同 difficult 统计口径差异很小，当前主要瓶颈是 oblique 视角。

## 建议展示内容

- 左侧展示三路模型和等权融合，右侧突出 oblique 错误样本。
- 用三个位置子组的 Recall 对比代替只展示总体指标。
- 标明 P2 与 standard 的选择来自验证实验。

## 可能问题

- 为什么两个分类器使用不同输入尺寸？
- 为什么 Missing Hole 不使用 P2？
- oblique 视角是数据不足还是物理不可见？
- difficult 样本的训练和测试口径是否一致？

# 第 10 页　关键决策三：独立阈值后执行 OR

## 本页作用

讲清系统最终判定规则，避免把两个概率理解为再次相加，或把检测框理解为直接决定剔除。

## 主要内容概括

两个专项先在自己的概率尺度上独立判定，只要任意专项命中，整颗齿轮即判为不合格。

## 详细内容与技术细节

    scratch_reject = scratch_probability ≥ 0.300273610279458
    missing_reject = missing_hole_probability ≥ 0.3413327979078584
    final_reject = scratch_reject OR missing_reject

- 两个专项的任务、温度校准和概率分布不同，没有证据支持把概率直接相加后使用统一阈值。
- OR 可以补回另一专项漏掉的缺陷，也会合并两个专项的误报集合。
- 同一齿轮同时命中两个专项时保留两个拒绝原因，但统计和串口只输出一次。
- 辅助框用于显示检测器可能关注的区域，最终结果依据融合概率和专项阈值。

## 建议展示内容

- 两个专项分别显示概率、阈值和布尔结果，再汇入 OR 门。
- 用交集示意展示 Recall 补回和 FP 合并。
- 明确标注“辅助框用于复核，不是最终判定条件”。

## 可能问题

- 为什么不用逻辑回归或另一个融合模型学习最终判定？
- 两个专项的误报是否高度相关？
- 是否评估过 AND 或其他级联规则？

# 第 13 页　实时软件架构、可观测性与安全边界

- 任一必要专项失败、空 ROI、哈希错误、NaN/Inf 或 CUDA OOM 会停止检测，不静默降级。
