# 阶段 0 收尾指令（整段复制给 Composer）

用法：整个代码块贴给负责板子和分析的 Composer。它自包含，不需要读任何分支文件。跑完后让它把汇总文件分段贴回给决策者。

```text
这是阶段 0 的收尾指令。请一次性完成下面所有内容，最后只交付一个汇总文件。中途遇到某一项失败，记录后继续做后面不依赖它的项，不要整体停下。

【零】全程规则
1. 板上同一时刻只允许一个 GPU 任务，所有构建和测量串行，单进程锁。不得与任何别的进程重叠。
2. 每次构建前后、每个时延区块前后记录温度和实际 pwm（风扇不再强改）。降频的数据标记作废并重测。
3. 分类器 logit 必须先 sigmoid，再温度缩放（c1 0.7，c2 2.05），取平均。检测器原始最大置信度再用 2.125 缩放。α=0.25。τ_prod=0.300273610279458，τ_sq=0.277518034469。千万不要再把 logit 直接传给 apply_temperature。
4. 每张表都带 n 和覆盖率（应是 514 张全覆盖，缺失要写）。去重键：每个 (cfg, model, build) 只能对应一个引擎。
5. 不确定的写"待核"，不要猜。不许改任何已有文件，不许改 gp/、model/、ultralytics/。

【一】Jetson 侧，按此顺序执行
J-1 分类器 v2：c1、c2 的 e1b、e1a、e2、e3、e4（MinMax）、e5、e6（DLA 回退构建），各 b1 到 b3，timing cache 禁用，workspace 4 GB。e3、e4 的校准缓存沿用，另外独立重跑一次校准，把新缓存的 sha 与旧缓存比较。DLA 严格构建不重复，保留已有失败日志的第一条 Error 即可。
J-2 固定 timing cache 组：仅 e2 和 e3（c1、c2）。第一次构建生成缓存，之后再用同一缓存构建 3 次。比较引擎哈希和分数是否逐位一致，并与 timing cache 禁用组比较。
J-3 R1：板上 PyTorch FP32，TF32 关，cudnn.deterministic，514 张，两个分类器，与 R0sq 比较。
J-4 检测器：确认板上 detector.onnx 的 SHA256 等于 e60dc5a186fba9b5b9c9f1f8ed95539819352fd917c3a125e40619b8b59fbda8。构建 e1b 和 e2，各 b1 到 b3。输入是 960×960 方阵（静态形状），uint8 RGB 张量在主机端除以 255。输出应为 [1,5,76500]，取第 5 通道（索引 4）的全局最大值作为 det_max_conf，同时记录 det_n_cand（该通道不小于 0.001 的个数）。不使用 NMS。每个引擎跑两遍比较是否逐位一致。失败原样记录，不改 workspace。
J-5 分数采集：所有成功引擎，514 张，每个引擎跑两遍比较逐位一致。
J-6 DLA 分配：每个 DLA 回退引擎（e5、e6 的 c1、c2，b1）给出 DLA 层数、GPU 层数、DLA 与 GPU 之间的切换次数（子图数）、reformat 层数、总层数；以 trtexec verbose 的列表为准，inspector JSON 交叉核对，贴出可区分 DLA 与 GPU 层的字段名。再给出 INT8 引擎（e3、e6）的 INT8 层数与 FP16 层数。
J-7 时延（最后做，板子最干净时）：对所有成功的引擎（分类器、检测器）测 engine（trtexec，纯引擎）和 e2e_core（主机张量已就绪，从 H2D 拷贝起到拿到输出止），每个 1000 次，3 个区块，稳态后测（预热判据：连续 3 个 30 秒窗口中位数变化小于 2%，且温度 1 分钟内变化小于 1 摄氏度，最长 15 分钟）。统计量：中位数、均值、标准差、p95、p99、最小、最大。再算门卫时延 gate=c1+c2 的顺序合计，R=gate/det，单分类器比，以及级联盈亏点 r*=1−gate/det。DLA 引擎额外测一次"分类器放 DLA 同时检测器在 GPU 并发"的整体时延（能做就做，不能做写原因）。

【二】分析（PC 或板外都可以，先用合成数据测试通过）
数据来源：PC 侧 r0rect、r0（即 R0sq）、r0t、r0c、o0，和 Jetson 侧全部引擎。
系统组合：对每个配置 X，构造"分类器 c1、c2 用 X，检测器用 D"。D 的取法：X 为 e1b 或 e1a 时 D=e1b；X 为 e2、e3、e4、e5、e6 时 D=e2（FP16 GPU 检测器是部署默认）。另外做 only_c1、only_c2、only_det 三个单模型替换场景（其余用 R0sq）。
参照两个：R0sq（隔离后端）与 r0rect（现网，总部署效应）。

B-1 门禁：r0rect 融合对 val_predictions.csv 的判定 0/150 一致；Jetson e1b 对 R0sq 的分类器 logit 最大差（预期 1e-5 量级，超过 1e-3 要说明）。
B-2 Δ 分布：每个 (配置, 模型) 给 logit 域的带符号 Δ=配置−R0sq，分 val 与 trainB、缺陷与正常，给 n、均值、标准差、median、q95、q99、最大绝对值。缺陷件另给"向下偏移"的尾部：max(0, R0sq−配置) 的 q95、q99、最大（这是门卫能否漏掉缺陷件的关键量）。trainB 是训练图，分数偏极端，标注只用于尾部估计。
B-3 翻转统计（只用 val）：按两个参照、两个阈值口径（(a) 两边 τ_prod，(b) 被测用 τ_sq 参照用 τ_prod），方向用 miss、false_alarm_added、false_alarm_removed、extra_catch（miss 指参照 REJECT 而被测 PASS 的缺陷件）。每格 k、n、Clopper-Pearson 95% 区间，k=0 给单侧上界。逐个翻转件列出 stem、标签、两个融合分数、与阈值的边距。边界判定：边距小于 4.46e-4 归边界，否则稳健。重建多次的，报每次构建的翻转张数和"任一构建翻转"的张数。
B-4 归因链：r0rect→R0sq（几何）→R0t（TF32）→R0c（硬件）→O0（导出）→R1（Jetson PyTorch）→e1b（TensorRT FP32）→e2（FP16）→e3/e4（GPU INT8）→e5/e6（DLA+GPU）。每步给融合分数 |Δ| 的最大值和 q99，以及分类器 logit 差的最大值和 q99。
B-5 重建差异（J7）：每个 (配置, 模型)：引擎哈希不同的个数、有逐位差异的图像数、最大 logit 差；timing cache 禁用组与固定组并列。
B-6 门卫候选：在 R0sq 上，对 G1（c1）、G2（c2）、Gm（两者平均）、F（融合），给 val AUROC；在召回 100% 与召回 42/43 时，能放行的正常件比例。
B-7 暴露曲线：对 Gm、G1、G2，取 t1 为缺陷件 R0sq 分数的 0%、5%、10% 分位数，每个配置给"R0sq 分数不低于 t1 而配置分数低于 t1"的缺陷件数（k/43，带区间）。再给 ρ=|Δ|/|分数−阈值| 大于 0.5 的件数（分缺陷、正常，不同阈值口径各一份）。
B-8 手册 7.4 的量：g=val 上 R0sq 融合分数落在 τ_prod±0.1 的图像，相邻排序分数间隔的中位数；每个配置的融合分数 |Δ| q99。只报数，判断由决策者做。
B-9 输出口径检查：每张表的 sigmoid 顺序、覆盖率、去重，逐表打勾。

【三】交付格式
一个汇总文件，总长度尽量在 400 行以内，只放表和结论数字，不放日志。结构：
1 环境事实：JetPack/L4T/TensorRT（trtexec 与 Python）/nvpmodel/风扇（各阶段实际 pwm 范围）/板温/降频记录/时钟偏差
2 构建表：配置×模型×build 的成功失败、引擎哈希、构建秒数、构建前后温度；失败的第一条 Error
3 J7、J-2：重建差异（含 timing cache 固定组）
4 J5：逐位复现结果
5 DLA 分配表（J-6）
6 INT8：校准缓存 sha 对照、与 R0sq 的 Pearson、带符号均值、AUROC
7 B-2 到 B-8 全部表
8 时延表（J-7）与 R、r*
9 R1 与 R0sq 比较
10 异常、未完成项及原因、与指令不一致的地方
11 需要用户在板上执行的恢复命令清单：gearpro.service、edgemedic.service 的启用，以及风扇和 jetson_clocks 的恢复
如果一次贴不完，分成两到三段贴给用户，每段标明页码。
```
