# 阶段 0 运行手册

> 2026-10-16。决策者：主对话 Claude。执行者：其他 AI（Composer 等），经 SSH 操作 Jetson Orin NX。
> 本手册是唯一规格。执行者遇到手册没覆盖的情况，写进情报单并停下，不要自行决定。
> "（我的判断）"表示推断，"待核"表示 NVIDIA 行为或数字未核实，"待定"表示数值要在运行中确定。

## 0 目的与总规则

阶段 0 回答一个问题：同一套 Scratch V5 模型从 PC 搬到 Orin NX，换 TensorRT 精度、INT8 校准、DLA（深度学习加速器）、引擎重建之后，阈值附近的放行或判废是否会变。它不产生论文结论，只产生"继续、调整、停止"的判断。

总规则，所有角色适用：

- 不修改 `gp/`、`model/`、`ultralytics/` 和根目录现有入口脚本。允许只读 import `gp.scratch_v5` 里的函数。
- 不查看、不人工浏览图像。对图像只做程序化检查（张数、尺寸、哈希）。
- 不编造数字。没测到的写"未测"。
- 不修改相机、串口、置信度阈值、模型路径等默认值。
- 每个脚本记录完整命令、版本和随机种子。所有输出带时间戳。
- 板上 `pip install` 必须在独立虚拟环境里做，并写进 `results/env/pip_changes.md`。不得升级或卸载系统自带的 TensorRT、CUDA、JetPack 包。
- 需要 sudo 而没有免密权限时，不绕过，不把密码写进任何文件，在情报单里写 BLOCKED 并停下。
- 板上如果有不是你启动的 GPU 进程（含 GearPro 服务），不要终止它，在情报单里写 BLOCKED。
- 大文件不进 git。协作协议见 `experiments/phase0/README.md`。

## 1 设计决策（对提示词 12 个问题与风险的结论）

1. 门卫分数。三个模型的原始量都保存：分类器 1 和 2 的原始 logit（温度缩放前），检测器的最高候选置信度。分析阶段定义四个门卫候选：G1 为分类器 1 温度缩放后的概率，G2 为分类器 2，Gm 为两者概率平均（与 `gp/scratch_v5.py` 里 `classifier_probability` 一致，是概率平均而不是 logit 平均），F 为现网融合分数，仅作参照。注意现网融合里检测器权重 0.75，分类器合计只占 0.25，所以 F 的翻转主要由检测器决定，不能直接代表门卫的翻转。阶段 0 因此必须做"单模型替换"分析，见 7.2。门卫的最终选择留到分析阶段，并看每个候选在 R0 上的 AUROC，以及"召回 100% 时能放行多少正常件"。门卫区分能力太差时，级联没有意义。

2. 隔离变量。对提示词的分层做了如下修改：
   - 新增 R0c：PC 上 PyTorch FP32 在 CPU 上运行。它与 GPU 型号无关，是跨机器的参考。
   - 新增 R0t：PC 上 PyTorch FP32 开启 TF32。PyTorch 默认 `torch.backends.cudnn.allow_tf32=True`（卷积默认允许，矩阵乘默认不允许），所以现网的 `val_predictions.csv` 很可能带有 TF32 卷积的误差（我的判断）。R0 必须显式把 `cudnn.allow_tf32` 和 `cuda.matmul.allow_tf32` 都设为 False。R0 与 R0t 的差是"TF32 本身"的噪声基线。
   - 新增 O0：PC 上 ONNX Runtime CPU FP32 跑导出的 ONNX。R0c 与 O0 的差是"导出误差"，用来把导出问题和 TensorRT 问题分开。
   - E1 拆成 E1a（TensorRT FP32，TF32 允许）和 E1b（TF32 关闭）。TensorRT 在 Ampere 上默认允许 TF32，关闭方式是清除 TF32 构建标志，trtexec 对应 `--noTF32`（待核，用 `trtexec --help` 和构建日志确认）。Orin 是 Ampere（sm_87），TF32 适用。
   - E5、E6 的 DLA 先尝试"不允许 GPU 回退"构建，失败再用允许回退构建。命名规则见 6.5。
   - 检测器只做 GPU 的 E1b 和 E2，INT8 放在 P3。
   - 全部配置一览见第 3 节。

3. 输入一致性。预处理只在 PC 上做一次，保存为 `.npy` 加 SHA256 清单，Jetson 只读这批文件，不在板上重新预处理。理由：PIL、torchvision 和 OpenCV 的版本不同，LANCZOS 缩放结果不一定逐位相同。唯一的例外是 J8 的端到端时延测试，它在板上做预处理，并顺带记录"板上预处理与 PC 张量的差异"。

4. 比较的量。你的判断大体成立：sigmoid 加温度缩放会压缩尾部，分类器应在原始 logit 上比较 Δ。但有两点修正。第一，判定翻转必须在融合分数上算，因为判定发生在融合概率与阈值之间；logit 域的 Δ 只能说明扰动大小。第二，检测器没有 logit。它的分数是"所有候选框的最大置信度"，我们定义检测器分数为该最大置信度（先于温度缩放）。NMS 不改变最大值，所以不同后端的 NMS 差异不影响这个分数，只影响框（我的判断，待在仓库自带的 `ultralytics/` 版本里核实：检查检测头是否为 end2end，确认 `predict()` 用的是哪个分支，把结论写进 `results/env/detector_head.md`）。所有后端的检测器输出都保存原始张量，由同一个主机端函数取最大值，不依赖各后端自己的后处理。Δ 同时报三种量纲：logit、温度缩放后概率、融合分数。

5. INT8 校准数据。校准集取训练集分层抽样 128 张（缺陷 42，正常 86，比例随训练集 119 比 245，种子固定为 2026），与验证集互不相交。互不相交用三重证据：stem 不交、文件 SHA256 不交、`cross_split_near_duplicates.csv`（仓库中为空表，说明 dhash 近重复检查无命中）。训练集剩余 236 张作为评估集 B。128 张对 EfficientNet-B0 和 ResNet18 的熵校准通常够用（我的判断，TensorRT 文档常见建议为数百张，待核），P3 里再做一次全部 364 张的敏感性对比。校准缓存按"模型、校准器、TensorRT 版本、校准集哈希"命名，重建时复用缓存，这样重建差异不含校准差异；另外把校准本身独立重跑 2 次，比较缓存文件哈希，检查校准是否确定。隐式量化的 Python 校准器接口在 TensorRT 10.1 之后标为弃用，10.7 中应该仍可用（待核），J3 第一步先用 8 张图验证它能不能在这块板上建出引擎。DLA 的隐式 INT8 要求 `IInt8EntropyCalibrator2`。校准批大小取 1，与部署一致。

6. DLA 可行性。我的推断是：EfficientNet-B0 的 SiLU 会拆成 Sigmoid 加逐元素乘，Squeeze-Excitation 里的通道缩放需要广播乘，ResNet18 末尾 12×12 的全局平均池化超出 DLA 池化窗口 1 到 8 的限制，这几处可能回退到 GPU（我的判断，全部待核）。因此手册设计成"先试后记录"，用 engine inspector 导出逐层设备分配，用回退层数量说话。

7. 引擎重建。每个配置用相同命令构建 3 次（b1、b2、b3），保存引擎 SHA256，比较三次的分数是否逐位一致。计时缓存分两组：free 组每次构建禁用计时缓存；fixed 组第一次构建生成缓存，之后 3 次复用同一缓存。主分数用 free 组。fixed 组只做 P2。

8. 运行环境。固定 nvpmodel 为板上最高性能模式（Super 刷机配置下通常叫 MAXN SUPER，待核，以 `nvpmodel -q` 与 `/etc/nvpmodel.conf` 为准），执行 `jetson_clocks`，风扇设为最大。分数与时钟无关，只有时延与时钟有关。预热方法见 6.8。环境温度由用户手写，没有就记"未知"。10W 与 15W 模式只启用一个 DLA 核（T7，官方文档，待核），所以阶段 0 不用这两种模式。

9. 时延。三种口径，定义见 6.8。统计量：中位数、均值、标准差、p95、p99、最小、最大。门卫时延比 R = (L_C1 + L_C2) / L_det，另报单分类器比 R1 = L_Ci / L_det。级联的期望时延是 L_g + r × L_det（r 为送检测器的比例），收益盈亏点 r* = 1 − L_g / L_det。L_g ≥ L_det 时级联没有省时间的可能。

10. 样本小。细节见 7.3。核心做法：Δ 描述的是后端差异而不是准确率，不需要独立测试集，所以可以把评估集 B 的 236 张加进来估计 Δ 的分布，样本量从 150 增加到 386。但评估集 B 是模型的训练图，分数偏极端，只用于 Δ 分布，不用于翻转张数。翻转张数只在验证集上报。零翻转时给上界，不写"没有问题"。

11. 判断标准。见 7.4，改成事先固定的数值规则。

12. 分工。PC 侧 P0 到 P5，Jetson 侧 J0 到 J9，分析侧 A1 到 A7，见第 5、6、7 节。

主动发现的风险与对策：

| 风险 | 对策 |
| --- | --- |
| 检测器 NMS 与后处理差异 | 分数取原始输出的最大候选置信度，不经过各后端后处理 |
| 检测器输入形状：`.pt` 的 `predict` 用最小矩形 letterbox，引擎是静态正方形 | R0-prod 保留现网路径用于复现；R0-fixed 与所有引擎共用 960×960 正方形输入，二者之差单独报告 |
| 动态形状与批大小 | 全部静态，批大小 1，与现网一致 |
| ONNX 算子集与导出器 | 固定 opset 17，使用传统导出器（`dynamo=False`），记录 torch 与 onnx 版本；O0 验证导出 |
| 板上 `trtexec` 与 Python 绑定版本不一致 | J0 强制核对，不一致则 BLOCKED。构建统一用 Python API，`trtexec` 只用于时延交叉验证和逐层信息 |
| 板上同时存在 TensorRT 10.3 与 10.7 | 记录两者路径，所有命令使用显式路径，`ldd` 检查实际加载的 `libnvinfer` |
| 引擎不能跨设备、跨版本 | 只在板上构建，文件名带 TensorRT 版本，不拷回 PC 当结果 |
| 校准图与验证图泄漏 | 三重证据，见决策 5 |
| 校准缓存不能跨版本复用 | 缓存名带版本与校准集哈希 |
| PyTorch 在 Jetson 上可能没装 | R1 标为 P2 可选，缺失时记录，不阻塞 P1 |
| 板上存储不足 | J0 检查 `df -h`，可用空间低于 20 GB 则 BLOCKED |
| cuDNN 非确定性算法 | R0、R1 设置 `cudnn.deterministic=True`、`cudnn.benchmark=False` |
| 同引擎两次运行不一致 | J5 逐位比较两次运行 |
| 热降频污染时延 | 记录温度与降频标志，降频的数据标记为不可用 |
| 同一零件多视角的相关性 | 阶段 0 按图像统计，在 summary 里明说，不报零件级结论 |

## 2 目录结构与文件命名

目录见 `experiments/phase0/README.md`。命名规则：

- 引擎：`{model}_{cfg}_{tc}_{bN}.engine`，例如 `c1_e2_free_b1.engine`。`model` 取 c1、c2、det，`tc` 取 free 或 fixed。DLA 引擎在 cfg 后加 `_dla0` 或 `_dla1`。
- 分数：每个 `(cfg, model, build)` 一次完整运行，写入 `scores_long.csv` 的若干行。
- 所有 CSV 用 UTF-8，无 BOM，浮点数用 `repr` 精度（17 位有效数字），不要格式化成 6 位。

## 4 数据与输入一致性

数据来源：分支 `origin/dataset`，路径 `dataset_defects/scratch_v5/`。图像是 Git LFS 对象。清单文件 `scratch_manifest.csv` 含 stem、split、label、尺寸、dhash、sha256。训练 364 张（缺陷 119，正常 245），验证 150 张（缺陷 43，正常 107）。

取图骨架（只拉需要的目录，不要拉整个分支）：

```bash
git fetch origin dataset
git worktree add --no-checkout ../gp-dataset origin/dataset
cd ../gp-dataset
git sparse-checkout set dataset_defects/scratch_v5
git checkout
git lfs pull --include="dataset_defects/scratch_v5/images/**"
```

`images/` 与 `classification/` 里可能是同一批图的两份拷贝，用 SHA256 比对确认后只用 `images/`。

三个子集：

| 子集 | 来源 | 张数 | 用途 |
| --- | --- | --- | --- |
| val | 验证集 | 150 | 主评估，翻转张数只在这里报 |
| calib | 训练集分层抽样 | 128 | 只用于 INT8 校准 |
| trainB | 训练集剩余 | 236 | 只用于估计 Δ 分布 |

张量文件：

- 分类器输入：`data/tensors/{stem}_cls384.npy`，float32，形状 [1,3,384,384]。两个分类器配置均为 384、同一归一化，应共用同一份。P1 步骤里要程序化确认两者预处理参数相同，不同则各存一份。预处理必须调用 `gp.scratch_v5.square_rgb_image` 加 `torchvision.transforms`，与 `predict()` 一致。
- 检测器输入：`data/tensors/{stem}_det960.npy`，uint8，形状 [1,3,960,960]，RGB，Ultralytics `LetterBox((960,960), auto=False, scaleup=True)` 之后的结果，填充值取 Ultralytics 默认。喂模型时统一在主机上执行 `x.astype(np.float32) / 255.0`。
- `data/tensors/tensor_manifest.csv`：`stem, kind, path, sha256, shape, dtype, letterbox_scale, pad_x, pad_y`。
- 传输：整个 `data/tensors/` 约 2.3 GB。用 rsync 或 scp 传到板上，传完在板上重算全部 SHA256 并与清单逐行比对，一个不符就 BLOCKED。

## 5 PC 侧任务（P 系列）

执行环境：有 CUDA 版 PyTorch 的机器，最好是 RTX 4060 Laptop。记录 GPU 型号与驱动，不同机器的 R0 不可混用。

P0 取图与清点。
- 步骤：按第 4 节取图。程序化检查：每个子集张数；每张图文件 SHA256 对 `scratch_manifest.csv`；val 与 train 的 SHA256 不交；`cross_split_near_duplicates.csv` 行数。
- 输出：`results/pc/manifest_images.csv`，列为 `stem, split, role(val|calib|trainB), label(normal|scratch), view, width, height, sha256_file, pc_fused_prob`。`view` 与 `pc_fused_prob` 仅 val 有，来自 `artifacts/evaluations/scratch-v5/val_predictions.csv`；其余填空。
- 验收：张数为 150、128、236；两个子集的 SHA256 交集为空。
- 校准抽样：种子 2026，分层，缺陷 42、正常 86，从训练集抽取，写入 `results/pc/calib_manifest.csv`。

P1 环境记录与 R0prod 复现。
- 步骤：记录 `torch`、`torchvision`、`ultralytics`（仓库自带）、`onnx`、`onnxruntime`、`numpy`、`Pillow`、`opencv` 版本与 GPU 型号，写入 `results/env/pc_env.json`。用 `ScratchV5Runtime.predict` 对 val 150 张（`cv2.imread` 后直接传入）跑现网路径，保存融合分数、分类器概率、检测器概率。
- 输出：`results/pc/r0prod_val.csv`，列 `stem, fused, classifier_prob, detector_prob`。
- 验收：与 `val_predictions.csv` 的 `scratch_probability` 比较。判定一致张数必须为 150。最大绝对差 ≤ 1e-3 为通过，依据是 TF32 的 10 位尾数对应约 5e-4 的相对误差量级（我的判断），超过这个量级说明预处理路径或权重版本不同。超过则 BLOCKED，写明差异最大的 5 个 stem，不要自己改预处理去凑。

P2 张量生成。
- 步骤：对三个子集共 514 张生成 cls384 与 det960 张量，写 `tensor_manifest.csv`。
- 验收：514 个 cls384 与 514 个 det960 文件；无 NaN；重复生成一次 SHA256 完全一致。

P3 参考分数 R0、R0c、R0t。
- 步骤：从张量文件读入（不再从图像预处理）。分类器直接取最后一层 logit，不做 sigmoid。检测器取原始输出张量（按 `results/env/detector_head.md` 的结论），主机端取最大候选置信度。R0 与 R0t 在 GPU 上，R0c 在 CPU 上。R0 设置 `cudnn.allow_tf32=False`、`cuda.matmul.allow_tf32=False`、`cudnn.deterministic=True`、`cudnn.benchmark=False`。
- 输出：追加到 `results/pc/scores_long.csv`，列定义见 5.1。
- 验收：514 张全覆盖，无 NaN。R0 与 R0c 的 logit 差、R0 与 R0t 的 logit 差分别记录最大值和 99 分位，写入 `results/pc/pc_noise_baseline.json`。这两个数是后续所有验收阈值的参照，无需先设阈值。同一配置运行两次，比较是否逐位一致。

P4 ONNX 导出与 O0。
- 步骤：分类器用 `torch.onnx.export`，opset 17，`dynamo=False`，输入名 `input`，形状固定 [1,3,384,384]，输出为 logit（不含 sigmoid）。检测器用 Ultralytics 导出，`format="onnx"`、`imgsz=960`、`opset=17`、`simplify=False`、`dynamic=False`、`half=False`、`nms=False`、`batch=1`。ONNX 放 `engines/onnx/`，记录 SHA256。O0 用 ONNX Runtime CPU 跑 514 张。
- 验收：O0 对 R0c 的分类器 logit 最大绝对差，阈值待定，依据是纯 FP32 同一计算图的差一般在 1e-5 量级（我的判断）。超过 1e-3 视为导出问题，BLOCKED 并给出最大差异的 stem。
- ONNX 传到板上，传完核对 SHA256。

P5 向 Jetson 侧交接。
- 完成 P0 到 P4 后写情报单 G0 的 PC 部分，并列出需要传输的目录与 SHA256 清单。

J1 接收与校验。

J2 功耗模式固定。

- 验收：`jetson_clocks --show` 显示频率已锁定。环境温度由用户填写，没有就写"未知"。

J3 INT8 可用性冒烟测试。

J4 构建引擎。
- 顺序：P1 配置先做，P2 在 G1 门禁之后做。

J5 采集分数。

- 验收：每个 `(cfg, model, build)` 对 514 张全覆盖，无 NaN；同一引擎两次运行逐位比较，结果写入 `results/jetson/runrun_determinism.csv`（列 `cfg, model, build_id, n_images, n_bitwise_diff, max_abs_diff`）。引擎能否跑通本身不设数值阈值，但 E1b 与 R0 的分类器 logit 差大于 0.05 时视为构建或导出错误，先排查（阈值是我的判断，待 E1b 的实际分布修正）。

J6 逐层设备分配。

- 输出：`results/jetson/layers_{engine名}.json`，以及汇总 `results/jetson/dla_layer_map.csv`，列 `engine, layer_name, layer_type, device(DLA|GPU|REFORMAT), precision`。
- 验收：每个 DLA 引擎都有记录。

J7 重建与计时缓存。
- b1 到 b3 的分数逐位比较，引擎哈希比较，输出 `results/jetson/rebuild_variance.csv`，列 `cfg, model, timing_cache, n_builds, n_distinct_engine_hash, n_images, n_images_with_any_bit_diff, max_abs_logit_diff`。
- fixed 组（P2）：第一次构建生成计时缓存，之后 3 次复用，同样比较。
- 验收：不设阈值，如实记录。

J8 时延。
- 三种口径：
  - engine：纯引擎时延。用 `trtexec --loadEngine` 加 `--useCudaGraph --noDataTransfers --warmUp=2000 --duration=30 --useSpinWait --percentile=99`（参数以 `trtexec --help` 为准），并用 Python 的 CUDA event 交叉验证。
  - e2e_core：张量已在主机内存，计时从 H2D 拷贝开始，到主机拿到输出为止。
  - e2e_full：从解码后的 ROI 图像数组开始，在板上做预处理（PIL LANCZOS、ToTensor），到取得输出为止。检测器含 letterbox 与取最大值。只用 val 的 150 张图，需要把这些图拷到板上并核对哈希。
- 预热：运行时每 30 秒计算一次中位数，连续 3 个窗口的中位数变化小于 2%，并且温度 1 分钟内变化小于 1 摄氏度，才进入计时，最长预热 15 分钟（这两个数值是我的判断，待定，第一次运行后按实际曲线修正）。
- 计时：单流、顺序执行、批大小 1，计时 1000 次，重复 3 个区块，区块之间循环使用 val 的 150 个张量。
- 统计：中位数、均值、标准差、p95、p99、最小、最大，以及 3 个区块中位数的范围。
- 门卫组合：C1 与 C2 顺序执行的合计时延，记为 gate。
- 记录：开始与结束的温度，是否降频（读 `tegrastats`、热区温度与频率），降频的区块标记 `throttled=1` 并重测。`tegrastats` 原始日志存 `logs/`。
- 输出：`results/jetson/latency_runs.csv`，列 `cfg, model, kind, nvpmodel, clocks_locked, trt_version, n_warm, n_iter, block, median_ms, mean_ms, std_ms, p95_ms, p99_ms, min_ms, max_ms, temp_start_c, temp_end_c, throttled, ts`。原始逐次时延存 `logs/latency_raw/`。
- 验收：每个 P1 配置至少有 engine 与 e2e_core 两种口径。

J9 交接。
- 写情报单 G1 或 G2，见第 8 节。

6.5 DLA 引擎的命名规则

- 只有"构建时未允许 GPU 回退并且成功"的引擎才叫 DLA 引擎，记 `DLA`。
- 允许回退才建成的，记 `DLA+GPU(n_gpu/n_total)`，其中 n_gpu 为落在 GPU 上的非重排层数。所有结果表与图例都必须使用这个标注。
- DLA 构建失败也是结果，记录 `status=fail` 与报错，不要换参数偷偷重试而不记录。

## 7 分析侧任务（A 系列）

执行环境：PC，离线。输入是 `results/pc/` 与 `results/jetson/`。先用合成数据写好并测试脚本，再读真实数据，避免看到数据后改指标。

A1 数据对齐与融合。
- 读 `scores_long.csv`，按 `(stem, cfg, model, build_id)` 对齐。
- 使用 `gp.scratch_v5` 里的 `apply_temperature` 和 `fuse_probabilities`（只读 import），参数取 `model/model2/inference_config.json`：温度 0.7、2.05、2.125，权重 0.25，阈值 0.300273610279458，融合分数大于等于阈值判废。检测器分数为 0 时按现网规则截为 1e-6。
- 注意 `logit_raw` 在分析侧用 float64 做 sigmoid，现网在设备上用 float32，二者差约 1e-7 量级，可忽略，但在复现报告里写明。
- 输出：`results/analysis/fused_scores.csv`，列 `cfg_c1, cfg_c2, cfg_det, build_c1, build_c2, build_det, stem, subset, label, g1, g2, gm, det_prob, fused`。

A2 Δ 表。
- 参照为 R0（GPU，TF32 关）。对每个 `(cfg, model, build)` 计算 Δ = 该配置值减 R0 值，三种量纲：logit（检测器用最大置信度的 logit，截断到 1e-6 与 1−1e-6）、温度缩放后概率、融合分数。
- 统计：均值、标准差、中位数、95 与 99 分位数、最大绝对值。分 subset（val、trainB）和 label（normal、scratch）分层。分位数的置信区间用图像级自助法（1000 次）。
- 同时输出 Δ 与 R0 分数水平的关系散点（Δ 是否随分数大小变化）。
- 输出：`results/analysis/delta_table.csv`、图 `delta_vs_score_*.png`。

A3 噪声基线链。
- R0c 对 R0（硬件），R0t 对 R0（TF32），O0 对 R0c（导出），R1 对 R0（Jetson 对 PC），E1b 对 R1（TensorRT 本身），E2 对 E1b（FP16），E3 对 E2（INT8），E5 对 E2（DLA）。这条链把变化逐层归因。输出 `results/analysis/attribution_chain.csv`。

A4 翻转统计（只用 val，相对 R0 的判定）。
- 场景：all_same（三个模型同一配置）与单模型替换 only_c1、only_c2、only_det（只有一个模型换成该配置，其余取 R0）。
- 方向分开：缺陷件由判废变放行（漏检方向），正常件由放行变判废。
- 对每格报告：翻转张数 k、总数 n、精确二项（Clopper-Pearson）95% 区间。k=0 时报告单侧 95% 上界：缺陷 43 张为 6.7%，正常 107 张为 2.8%（由 1 − 0.05^(1/n) 计算）。重建多次的，分别报每次构建的翻转和"任意一次构建翻转"的张数。
- 输出：`results/analysis/flips.csv`，列 `cfg, scenario, build_scope, subset, label, direction, n, k, ci_lo, ci_hi`。

A5 暴露曲线与近翻转。
- 对门卫候选 G1、G2、Gm、F，在 R0 分数上扫一组假想的 t1：取缺陷件 R0 分数的 0%、5%、10% 分位数，以及 F 的现网阈值。对每个 t1，统计缺陷件中"R0 分数不低于 t1 但引擎分数低于 t1"的张数（假想漏检）。
- 近翻转指标：对每张图，ρ = |Δ| / |分数 − 阈值|，同向时 ρ > 1 即翻转。报告 ρ > 0.5 的张数，作为比"0 或 1"更连续的风险指标。
- 插值预测翻转数：用所有图（val 与 trainB）的 Δ 经验分布，对 val 每张图计算"Δ 超过其边距且方向正确"的经验概率，求和得到预期翻转数，与观测值比较。
- 输出：`results/analysis/exposure_curve.csv`、`results/analysis/near_flip.csv`。

A6 时延与级联盈亏。
- 汇总 `latency_runs.csv`。计算 R、R1 与盈亏点 r*。对 engine 与 e2e_core 分开出表。
- 输出：`results/analysis/latency_summary.csv`。

A7 一页结论。
- 按第 10 节模板写 `results/analysis/phase0_summary.md`，并回写到 `reports/papers/阶段0_结论.md`。给出继续、调整、停止的建议和依据，不要写超出数据的话。

### 7.3 样本太小时的报告规则

- 翻转张数永远带精确二项区间；零翻转必须给上界。
- 缺陷和正常分开，方向分开。
- 报告"风险集合"大小：R0 融合分数落在阈值 ± q99(|Δ|) 之内的 val 图像张数，分缺陷和正常。
- 单个量的点估计不能脱离样本量，所有表头都带 n。
- 门卫分数的翻转只在假想 t1 下计算，t1 是占位值，不是论文里的阈值。
- 现网融合阈值 0.3003 与融合权重来自对这 150 张验证图的选择，不要把这 150 张上的漏检率当作论文结果。

### 7.4 判断标准（事先固定）

记 τ = 0.300273610279458，g 为 val 中 R0 融合分数落在 τ ± 0.1 之内的图像相邻分数间隔的中位数，q99 为某配置在融合分数上的 |Δ| 的 99 分位数。

| 观测 | 结论 |
| --- | --- |
| E3、E4、E5、E6 任一配置在 val 上出现缺陷件被翻成放行，或 q99 ≥ g，或 ρ > 0.5 的缺陷件非空 | 继续，题目有可测的效应 |
| 仅 E2 以外的配置在正常件上翻转，缺陷件无翻转，q99 < g | 调整，叙述改为误报方向或成本，继续观察 |
| 所有 GPU 与 DLA 配置翻转为 0，q99 < g，ρ > 0.5 的件为空，且重建差异为 0 | 效应在这套模型上不可测。必须同时写明：val 上缺陷件 0/43 的单侧 95% 上界是 6.7%，不能据此断言没有问题。建议改讲法，不建议直接停 |
| DLA 引擎建不出，或回退层占比高（阈值待定，由 J6 的实际分布决定） | 记为可部署性结果，缩小 DLA 部分 |
| 门卫时延 L_g 不小于检测器时延 L_det | 级联省不下时间，只保留保证部分 |
| 门卫在 R0 上无法在召回 100% 时放行足够多的正常件（放行率低于 20%，数值是我的判断，待定） | 门卫区分能力不足，换门卫候选或换级联叙述 |

其中 g 与 0.5 是我的判断，因为阶段 0 的目的是判断方向。如果结果恰好落在边界附近，决策者会根据 A5 的曲线人工判断。

## 11 实验作废需要重做的清单

- 张量哈希在 PC 与板上不一致，或有任何分数没有使用清单里的张量。
- R0prod 无法复现 `val_predictions.csv`，且原因未查明。

## 12 待核事项（执行者只管记录，不要凭记忆下结论）

- TensorRT 在 Ampere 上默认允许 TF32，以及 `--noTF32` 对应的构建标志：用 `trtexec --help` 与 Python 的 `BuilderFlag` 枚举确认。
