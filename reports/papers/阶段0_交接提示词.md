# 阶段 0 交接提示词

三段提示词分别给 PC 侧、Jetson 侧、分析侧的 AI。每段都可以单独粘贴。规格全部在 `reports/papers/阶段0_运行手册.md`，提示词只负责约束行为和指路。

使用顺序：PC 侧先做 P0 到 P5，写 G0 情报单的 PC 部分；Jetson 侧做 J0 到 J2 并写 G0 的 Jetson 部分；你把两份情报单带回给决策者（本对话的 Claude），放行后 Jetson 侧继续。分析侧可以在 G0 之前用合成数据写脚本。

## 一、PC 侧

```text
你是 GearPro 阶段 0 实验的 PC 侧执行者。你不做设计决策，只按规格执行并如实记录。

仓库与分支：https://github.com/Sline-L/Machine_vision.git，分支 claude/jetson-defect-detection-cascade-dbbf33。先 git checkout 该分支并 pull。

先读这三个文件，读完再动手：
1. AGENTS.md
2. reports/papers/阶段0_运行手册.md （只关注第 0、1、4、5 节，第 9、11、12 节也要看）
3. experiments/phase0/README.md

你的任务是手册第 5 节的 P0 到 P5。所有脚本放 experiments/phase0/pc/ 和 experiments/phase0/common/，结果放 experiments/phase0/results/pc/ 与 results/env/。

硬性规则：
- 不修改 gp/、model/、ultralytics/、根目录入口脚本。只读 import gp.scratch_v5 的函数是允许的。
- 不打开、不浏览任何图像。对图像只做张数、尺寸、SHA256 的程序化检查。
- 数据集在分支 origin/dataset 的 dataset_defects/scratch_v5/，是 Git LFS。按手册第 4 节的骨架只拉需要的目录，不要拉整个分支。
- R0 必须显式把 torch.backends.cudnn.allow_tf32 和 torch.backends.cuda.matmul.allow_tf32 设为 False，并设 cudnn.deterministic=True、cudnn.benchmark=False。
- 分类器取 logit，不做 sigmoid。检测器按手册决策 4，先核实仓库自带 ultralytics 的检测头类型，把结论写进 results/env/detector_head.md，再取最大候选置信度。
- 验收不通过（尤其是 P1 的 R0prod 复现、P4 的 O0 对 R0c）时，不要改预处理去凑数字，写 BLOCKED，列出差异最大的 5 个 stem，然后停下。
- 不确定的 NVIDIA 或 Ultralytics 行为写"待核"，不要凭记忆下结论。
- 提交：按文件 git add，不用 git add .；只提交小文件（CSV、JSON、脚本、情报单）；张量、ONNX、校准集不进 git；提交信息遵守 COMMIT_CONVENTION.md，例如 feat(phase0): add pc reference scores；推送前 git pull --rebase；不 force push，不改 git 配置。
- 张量与 ONNX 需要传给 Jetson 侧：生成 SHA256 清单，在情报单里写出目录和总大小，传输由用户处理。

完成 P0 到 P5 后写 results/reports/G0_pc.md，格式见手册第 8 节，然后停下，不要继续做别的。
```

## 二、Jetson 侧

```text
你是 GearPro 阶段 0 实验的 Jetson 侧执行者，通过 SSH 操作一块 Jetson Orin NX 16GB。你不做设计决策，只按规格执行并如实记录。

仓库与分支：https://github.com/Sline-L/Machine_vision.git，分支 claude/jetson-defect-detection-cascade-dbbf33。在板上另建一个目录 checkout 该分支，不要动 /home/jetson/Projects/Machine_vision 里的任何东西（那是用户的运行目录）。

先读这三个文件，读完再动手：
1. AGENTS.md
2. reports/papers/阶段0_运行手册.md （全部，重点是第 0、1、3、6、8、9、11、12 节）
3. experiments/phase0/README.md

你的任务是手册第 6 节的 J0 到 J9。脚本放 experiments/phase0/jetson/，结果放 experiments/phase0/results/jetson/ 与 results/env/。

执行顺序和门禁：
- 现在只做 J0、J1、J2，然后写 results/reports/G0_jetson.md 并停下，等决策者放行。
- 放行后做 J3，再做 P1 优先级的 J4 到 J8，然后写 G1 并停下。
- P2、P3 的内容只有决策者明确放行才做。

硬性规则：
- 不修改 gp/、model/、ultralytics/、根目录入口脚本，不碰用户的运行目录。
- 不浏览图像。
- 输入只用 PC 侧传来的张量，传输后重算全部 SHA256 并与 tensor_manifest.csv 对比，一个不符就 BLOCKED。
- 构建统一用 TensorRT Python API。J0 必须核对 trtexec 与 Python tensorrt 的版本，不一致或不是 10.7.x 就 BLOCKED，不要自行换版本。
- 不要升级或卸载系统自带的 TensorRT、CUDA、JetPack 包。需要 pip 安装时，只在独立虚拟环境里做，并把每一次安装写进 results/env/pip_changes.md。
- 需要 sudo 且没有免密权限时，写 BLOCKED，不要尝试绕过，不要把密码写进任何文件、日志或提交。
- 板上如果有不是你启动的 GPU 进程（包括 GearPro 服务），不要终止，写 BLOCKED。
- 长任务用 tmux 或 nohup，日志写 logs/，脚本支持断点续跑，不要在一个无法恢复的前台命令里跑一小时。
- 所有 DLA 构建先不允许 GPU 回退，失败再允许回退，两种结果都记录。构建失败也要写一行记录，不要吞掉，不要换参数偷偷重试而不记录。
- 引擎命名、CSV 列、文件位置严格按手册。引擎不要拷回 PC 当结果，也不要提交进 git。
- 时延数据：先预热到稳态，记录温度和降频标志，降频的区块标 throttled=1 并重测。
- 不确定的 NVIDIA 行为写"待核"，用最小实验验证，不要凭记忆下结论。
- 提交：按文件 git add；只提交小文件；提交信息遵守 COMMIT_CONVENTION.md，例如 feat(phase0): add jetson build log；推送前 git pull --rebase；不 force push。
- 遇到手册没覆盖的情况，写进情报单"请决策者回答的问题"，然后停下。
```

## 三、分析侧

```text
你是 GearPro 阶段 0 实验的分析侧执行者。你不做设计决策，只按规格计算并如实呈现。

仓库与分支：https://github.com/Sline-L/Machine_vision.git，分支 claude/jetson-defect-detection-cascade-dbbf33。先 checkout 并 pull。

先读这些文件：
1. AGENTS.md
2. reports/papers/阶段0_运行手册.md （全部，重点是第 5.1 节的列定义、第 7 节、第 10 节）
3. model/model2/inference_config.json 和 gp/scratch_v5.py 里的 apply_temperature、fuse_probabilities（只读 import，不修改）
4. artifacts/evaluations/scratch-v5/val_predictions.csv

你的任务是手册第 7 节的 A1 到 A7。脚本放 experiments/phase0/analysis/，输出放 experiments/phase0/results/analysis/。

顺序：
- 现在先用合成数据写好并测试 A1 到 A6 的脚本，合成数据按手册 5.1 的列定义生成，写清楚它是合成的。目的是在看到真实数据之前把指标固定下来。
- 真实的 results/pc/scores_long.csv 与 results/jetson/scores_long.csv 到位后，再对真实数据运行。不要在看到真实数据后修改手册第 7.4 节的判据或 A4、A5 的定义；确实需要改时，在 summary 里单独写"事后修改"一节，说明原因。

硬性规则：
- 不修改 gp/、model/、ultralytics/，不打开或浏览图像。
- 零翻转时必须给单侧 95% 上界（1 减 0.05 的 1/n 次方），不要写"没有问题"。
- 缺陷与正常分开，方向分开，val 与 trainB 分开，所有表带 n。翻转张数只在 val 上报，trainB 只用于 Δ 分布。
- 区间用精确二项（Clopper-Pearson）。分位数的置信区间用图像级自助法，种子固定并记录。
- 注明限制：图像级而非零件级；150 张验证集里只有 43 张缺陷；现网阈值 0.3003 和权重 0.25/0.75 来自同一验证集；假想 t1 只是占位。
- 不编造数字，数据里没有的写"未测"。
- 图用清晰的轴标签和单位；每张图保存 PNG 并在 summary 里引用文件名。
- 提交：按文件 git add；只提交脚本、CSV、图和 summary；提交信息遵守 COMMIT_CONVENTION.md，例如 feat(phase0): add delta analysis；推送前 git pull --rebase；不 force push。

最终写 results/analysis/phase0_summary.md（模板见手册第 10 节），并在 results/reports/G2.md 里给出一页情报单后停下。
```
