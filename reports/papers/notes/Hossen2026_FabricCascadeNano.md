# Hossen 2026 织物缺陷两级级联（Jetson Nano）及加速归因分解
- 完整引用：Rasel Hossen, Diptajoy Mistry, Mosaddek Hossain Kamal (Univ. of Dhaka), "Low Cost Two-Stage Fabric Defect Detection at the Edge", arXiv:2608.14727v1 [cs.CV], 12 Aug 2026. 预印本。
- 来源核实：OA_arXiv/2608.14727.pdf；首页 v1，12 Aug 2026，14 页；与已知元数据无差异。
- 阅读深度：全文（正文 1–8 节、表 1–8、参考文献前部；参考文献后部与附图未细看）。
- 一句话：用自编码器（autoencoder）做第一级异常筛选、YOLOv5n 只处理被标记的帧，在 Jetson Nano 上以 TensorRT FP16 部署；核心发现是 1.36× 端到端加速里 91% 来自 JPEG 解码与推理重叠，级联本身只贡献 8.9%。
- 问题设定：输入为织物图像（Stage 1 用 120×120 RGB，Stage 2 用 320×320），四类缺陷（fly yarn、hole、oil spot、thread error）。Stage 1 只用无缺陷图训练，用重构误差对阈值 τ 做放行/转发；无任何统计保证，阈值是经验选取。
- 方法：Stage 1 为 41,441 参数的卷积自编码器（解码器注意力门 + 边缘加权重构损失 + 对冻结 YOLOv5n 特征的蒸馏，kd=0.3，三项只作为整体评估，未消融）；Stage 2 YOLOv5n。运行时为 loader 线程 + Stage 1 主线程 + Stage 2 子进程（有界队列深度 8）。一阶时间模型 wall ≈ max(AE, φ·YOLO) + overhead（式 3）；转发率 φ = π·r + (1−π)·f（式 6，π 患病率、r 召回、f 假阳率）。
- 保证 / 结论：
  - 加速分解（§6.4，式 4–5）：总墙钟差 101.40−74.33 = 27.07 ms/图；推理差 47.77−45.36 = 2.41 ms（8.9%），非推理开销差 53.63−28.97 = 24.66 ms（91.1%）。级联使推理时间仅降 5.1%（φ=0.534）。
  - 作者自己估计：若 YOLO-only 也用线程加载，可达约 18.65 FPS，高于两级的 13.45 FPS，优势"反转为约 0.72×"；这是由式 3 推出的估计，未实测（L3）。
  - 转发受假阳率限制：85% 的转发帧是误报（§6.5）；φ 从 0.534（π=0.08）仅降到 0.499（π=0.01）。
  - 作者明确定位为"辅助分诊，而非自主验收"。
  - 召回 20/20（95% CI 0.83–1.00，Clopper-Pearson）是样本内（in-sample）校准结果，阈值 τ=0.00245 就是在同一 249 图上选的（§4.2.6，L1）；无阈值扫描/ROC。
- 实验：
  - 数据：4,188 张图，3,939 训练 / 249 留出基准（20 缺陷、229 正常，患病率 8.0%）；Stage 1 用约 800 张正常图训练；其中 1,000 张为 Gemini 合成图，仅用于训练（表 1）。
  - Stage 1（表 4，τ=0.00245）：基础 AE 召回 19/20、FP 140/229（FPR 0.611）；改进 AE 20/20、FP 113/229（FPR 0.493）；FP 下降 19.3%（p=0.011）。"全判正常"基线准确率 0.920 高于改进 AE 的 0.546。参考阈值 τref≈0.0189（正常验证集 99 百分位），未评估。
  - Stage 2（表 5/6）：YOLOv5n mAP50 0.742、mAP50-95 0.363、框级召回 0.637；图像级准确率 199/202；选型与评估用同一 202 图集（偏乐观，L9）。
  - 硬件：Jetson Nano 开发套件，L4T R32.7.2，JetPack 4.6，TensorRT 8.x，MAXN 模式，4GB 内存，单次代表性运行（无方差，L10）。
  - 表 7：YOLO-only 47.77 ms 推理 / 101.40 ms 墙钟 / 9.86 FPS；AE-only 27.29 / 82.25 / 12.16；两级并行 45.36 / 74.33 / 13.45 FPS。
  - 表 8（投影，非测量，假设召回不变）：FPR 降到 0.01 时推理节省约 44.6%。
- 局限：作者承认（§7 L1–L12）：阈值在评估集上选；仅 20 个缺陷；无线程化 YOLO-only 对照；无现代异常检测基线（PatchCore 等）；无 ROC/AUROC；无逐类指标；无组件消融；单次计时；磁盘读取非实时相机。我的判断：数据来源混杂、样本极小；功耗（10W）只作为约束提及，未见实测能耗；未使用 DLA（Nano 无 DLA）。
- 和我们的关系：需区别 + 重要反例/警示。关键点：(1) 这是"便宜筛选 + 贵检测器"的两级级联且部署在 Jetson（Nano）TensorRT 上，在"视觉缺陷 + 级联 + 边缘部署"三项上与我们相近；但没有零件级高概率漏检保证（阈值经验选取、样本内、无统计保证），所以不满足我们声称（a）所要求的"保证"一项。(2) §5.2 与 L8 明确指出：阈值在 FP32 上校准，FP16 引擎上未重新验证筛选精度，并把它列为"未量化风险"——这正是我们 H 问题的动机，但本文只是指出而未研究。(3) 其"加速主要来自数据通路"的警示迫使我们在报告计算/能耗节省时用同等流水线的对照、并给出 φ 分解。(4) 其 φ = π·r+(1−π)·f 分解可直接借用来解释我们的检测器调用率。
- 可引用的句子：(转述) 在 Jetson Nano 上，1.36× 端到端加速中 91.1% 来自解码重叠，级联仅贡献 8.9%（§6.4）。(转述) 作者在 FP32 上校准阈值并直接部署 FP16 引擎而未重验筛选精度，视为未量化风险（§5.2，L8）。(转述) 转发率受 Stage-1 特异度而非缺陷稀有度限制，85% 的转发帧为误报（§6.5）。
- 疑点：表 7 的 "Inf." 与 "Overhead" 列在文本提取中错位，两级行 Inf.=45.36、Wall=74.33、Overhead=28.97、FPS=13.45 是按行推断的，且与式 4–5 的数字吻合，可信；但建议看原图表核对。"1.36×"与 13.45/9.86=1.364 一致。作者称实现了"完整"部署，但代码仅"按合理请求提供"，不可复现。
