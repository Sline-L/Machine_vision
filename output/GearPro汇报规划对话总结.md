## 2. 对仓库的整体理解

GearPro 是运行在 Jetson 或 Linux 工控机上的齿轮在线视觉检测系统。当前 main-web 分支采用：

- FastAPI 提供后端 API、会话、控制和状态推送。
- Vue 3 提供局域网浏览器控制台。
- OpenCV 负责相机采集。
- 独立线程负责模型加载和推理。
- 串口负责向外部执行机构发送检测结果。

当前视觉链路为：

    相机或测试视频
    → Model1 定位齿轮
    → 裁剪并外扩齿轮 ROI
    → Scratch V5 判断划痕
    → Missing Hole V1 判断缺齿或缺口
    → 两个专项分别过阈值后执行 OR
    → Web 展示、统计和串口输出

系统的主要工程特征包括：

- 相机线程只保留最新帧，避免队列积压。
- 推理线程与 FastAPI 事件循环分离。
- 模型首次启动时加载并预热，暂停和恢复时复用模型。
- 多客户端可以同时查看，但只有一个客户端持有操作权。
- 视频测试模式主动禁用串口。
- 运行状态通过 SystemSnapshot v2 暴露。
- 当前实现支持 FULL、SPARSE 和 SAFE_STOP 推理档位。
- 必要专项失败、权重哈希错误、空 ROI、NaN/Inf 或 CUDA OOM 时停止检测，不静默降级。

当前分支具备遥测、健康状态和有限安全控制基础，但不能宣称完整 LLM 诊断、Guardian 或自治恢复已经完成。

## 3. 模型与判定逻辑

### 3.1 两阶段检测

系统没有直接在整张相机图像上判断缺陷，而是先用 Model1 定位齿轮，再裁剪高分辨率 ROI。

采用该方案的主要原因是：

- 划痕尺寸小、对比度低。
- 整图缩放会进一步减少划痕占用的像素。
- 背景和姿态会增加干扰。
- ROI 可以把输入分辨率集中在齿轮区域。

定位框在宽度和高度方向各外扩 4%，用于保留边缘缺陷和少量上下文。

### 3.2 Scratch V5

Scratch V5 由两路分类器和一路检测器组成：

- EfficientNet-B0。
- ResNet18。
- YOLO26-P2。

融合方式为：

    scratch_probability
    = 0.25 × classifier_probability
    + 0.75 × detector_probability

发布阈值为 0.300273610279458。

锁定测试结果：

- 样本总数 150 张，其中划痕 31 张、正常 119 张。
- Recall：0.8065。
- Precision：0.5556。
- FPR：0.1681。
- TP/FP/TN/FN：25/20/99/6。

主要问题是低对比、小面积划痕漏检，以及高光和正常加工纹造成的误报。

### 3.3 Missing Hole V1

Missing Hole V1 同样由两路分类器和一路检测器组成：

- EfficientNet-B0。
- ResNet18。
- 标准 YOLO26n 单类检测器。

融合方式为：

    missing_hole_probability
    = 0.50 × classifier_probability
    + 0.50 × detector_probability

发布阈值为 0.3413327979078584。

锁定测试结果：

- 样本总数 150 张，其中缺陷 44 张、正常 106 张。
- Recall：0.8182。
- Precision：0.9000。
- FPR：0.0377。
- TP/FP/TN/FN：36/4/102/8。

位置子组 Recall：

- bottom：0.9167。
- side：1.0000。
- oblique：0.5882。

斜视缺口是 Missing Hole 当前最明显的瓶颈。P2 在该任务上没有表现出稳定优势，因此保留标准检测头。

### 3.4 最终 OR 判定

两个专项不再融合成一个总分，而是分别使用自己的概率和阈值：

    scratch_reject = scratch_probability ≥ scratch_threshold
    missing_reject = missing_hole_probability ≥ missing_hole_threshold
    final_reject = scratch_reject OR missing_reject

OR 能补回另一个专项漏掉的缺陷，也会合并两个专项的误报。

联合锁定测试结果：

- 任意缺陷 Recall：0.8873。
- Precision：0.7778。
- FPR：0.2278。
- TP/FP/TN/FN：63/18/61/8。

作为对照，统一 EfficientNet-B0 任意缺陷模型的结果为：

- Recall：0.7606。
- Precision：0.6207。
- FPR：0.4177。
- TP/FP/TN/FN：54/33/46/17。

双专项优于当前统一模型，但仍未达到 Recall ≥ 0.95 且 FPR ≤ 0.20 的阶段目标，因此当前成果应称为“可运行基线”，不能称为生产最终模型。

## 5. 汇报思路的调整

最初讨论重点偏向“打印讲稿怎样组织”。随后明确，真正需要优化的是：

- PPT 的信息结构。
- 演讲的技术主线。
- 各页之间的因果关系。
- 如何向专业老师展示技术判断，而不是只介绍功能。

最终选择的叙事方式是：

> 当前结论先行，再用关键决策链解释结果

没有采用两种极端方式：

- 不采用完整版本时间线，因为容易变成训练日志。
- 不只讲最新成果，因为无法体现架构变化的依据和研究深度。

探索路线只保留真正影响决策的内容：

1. 整图缩放损失微小缺陷信息，因此采用定位加 ROI。
2. 统一模型泛化不足，因此拆分两个专项。
3. Scratch 使用 P2，Missing Hole 使用标准检测头，因为不同任务的验证结果不同。
4. 两个专项采用独立阈值和 OR。
5. 错误样本指向数据、成像和视角问题，因此下一步不应只增加训练轮数。

## 7. 从《优化方案》中采用的内容

《优化方案》中可以进入汇报的内容分为三类。

### 7.1 已经落实

- 两阶段定位与 ROI。
- 按工件和近重复组隔离数据。
- 双专项模型拆分。
- Scratch 使用 P2。

### 7.2 已经尝试但没有稳定收益

- 单纯提高到更高输入分辨率。
- 继续增加训练 epoch。
- 普通 hard-case 或 CLAHE 组合。
- 普通滑窗局部检测。
- Missing Hole 使用 P2。

### 7.3 下一阶段候选方案

- 稳定照明和真实工业相机采集。
- 上下相机或多视角采集。
- 按实体齿轮建立多视角 group。
- 补充低对比划痕和高光正常负样本。
- 几何归一化、齿圈裁剪、旋转校正和极坐标展开。
- P2 轻量化、Neck 单变量消融和有限注意力实验。
- 知识蒸馏。
- Jetson 分项性能剖析。
- .pt 基线、FP16 TensorRT、必要时 INT8。
- 结构化剪枝、减少内存复制，最后才考虑自定义 CUDA。

不应直接作为结论表述的内容包括：

- 固定认为 7:2:1 是唯一正确的数据比例。
- 笼统认为学习率过小就是过拟合原因。
- 认为所有小目标任务都必须使用 P2。
- 未经回归测试就声称 INT8 对精度影响很小。

## 8. 下一阶段优化的推荐顺序

最终确定的优化顺序是：

### 第一阶段：成像和数据

- 验证划痕在原图和模型输入中的实际像素尺寸。
- 稳定焦距、曝光、照明和工件姿态。
- 补采低对比划痕、斜视缺口和高光正常样本。
- 对多视角数据按实体齿轮分组。
- 建立新的 blind test。

### 第二阶段：几何和模型结构

- 估计齿轮中心、直径和尺度。
- 比较不校正、旋转校正和极坐标展开。
- 对 P2、P3、P5 和 Neck 做单变量消融。
- 比较完整 P2、减少通道和轻量分支。
- 必要时研究知识蒸馏。

### 第三阶段：Jetson 部署

- 分解相机、模型、绘图、JPEG 和 Web 传输耗时。
- 建立 .pt 精度与性能基线。
- 优先转换 Model1 到 FP16 TensorRT。
- 重新验证专项概率、融合和最终 OR。
- 只有在必要时再评估 INT8、结构化剪枝、零拷贝和 CUDA。

## 9. PPT 与 PDF 的排版结论

最终建议是：

> 使用 PowerPoint 制作，同时导出 PDF 作为现场展示和备用版本。

选择 PowerPoint 的原因：

- 模型结构、流程图、错误样本和界面截图较多。
- 图片裁剪和对齐比 LaTeX 更方便。
- 可以快速根据老师意见修改。
- 使用母版可以实现稳定的双层导航。
- 导出 PDF 后可以获得稳定的字体和显示效果。

LaTeX Beamer 更适合大量复杂公式、自动化生成和作者已经非常熟悉 LaTeX 的情况。当前汇报需要频繁进行图片、流程和空间布局调整，因此 PowerPoint 更合适。

## 10. 双层进度条设计

一级进度条用于显示整个汇报的大板块，二级进度条显示当前板块内部的具体主题。

### 10.1 一级板块

| 一级板块 | 页码 | 内容 |
|---|---:|---|
| 项目现状 | 1–2 | 汇报范围、当前成果 |
| 评价与数据 | 3–5 | 指标、处理流程、数据可信度 |
| 技术决策 | 6–12 | ROI、双专项、模型、融合、结果、错误分析 |
| 软件落地 | 13–15 | 软件架构、工程闭环、现场演示 |
| 优化路线 | 16–18 | 成像数据、几何模型、Jetson 部署 |
| 总结讨论 | 19 | 阶段结论和讨论 |

### 10.2 二级主题

- 项目现状：汇报范围｜当前成果。
- 评价与数据：任务指标｜处理流程｜数据可信度。
- 技术决策：ROI 方案｜统一与专项｜Scratch｜Missing Hole｜OR 判定｜核心结果｜错误分析。
- 软件落地：架构与安全｜工程闭环｜现场演示。
- 优化路线：成像与数据｜几何与模型｜Jetson 部署。
- 总结讨论：阶段结论。

二级条只显示当前一级板块内部的主题，不一次展示全部 19 页。

### 10.3 视觉规则

- 16:9 画布。
- 白色或极浅灰背景。
- 黑、深灰、浅灰加一个蓝色强调色。
- 当前章节深色高亮，其他章节使用浅灰。
- 一级条比二级条更高、更醒目。
- 封面可以不显示进度条，从第 2 页开始显示。
- 不使用复杂动画，翻页时只改变高亮位置。
- 每页只表达一个主要判断。
- 每页优先采用“一张主图加一块结论”，避免密集卡片。
- 不需要 Logo、渐变背景和装饰性图案。

### 10.4 PowerPoint 实现方法

1. 在幻灯片母版中固定标题区域、一级进度条、页码和内容边界。
2. 为六个一级板块分别建立一个母版版式。
3. 二级进度条随页面复制，并修改当前高亮项。
4. 所有条目保持相同高度、字体和间距。
5. 不需要为 19 页分别制作 19 个母版。
6. 完成后同时保存 PPTX 和 PDF。

## 11. 演讲表达原则

- 开头两页先告诉老师当前结论。
- 不讲 Batch、Epoch 等基础概念，默认老师理解机器学习基础。
- 重点讲数据隔离、技术决策、融合方式、阈值纪律和错误模式。
- 所有技术路线都说明选择依据和代价。
- 主动承认 Recall、FPR 和真实设备验收差距。
- 把优化方案表达为“假设—实验—评价指标”，不表达为已经完成。
- 现场演示只证明功能闭环，不替代正式验收。
- 结尾主动邀请老师讨论成像、实验设计和部署优先级。
